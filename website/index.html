Two steps

  1. 1

    Analyze

    npx nest-cartograph analyze

    Reads your tsconfig.json and writes cartograph.json. It is deterministic — no timestamps, everything sorted — so you can commit it and review architecture changes in a pull request.

  2. 2

    View

    npx nest-cartograph view

    Opens an interactive map in your browser. Or write one self-contained HTML file with -o map.html and share it — no server needed.

Run npx nest-cartograph with no command to do both, without writing the JSON.

What you get

  • Follow one flow

    Search a name and see only what it calls and what calls it, from controllers down to repositories and Kafka producers.

  • Catch circular imports

    Modules that import each other are flagged. --fail-on-cycles fails CI when one is not wrapped in forwardRef().

  • Jump to the code

    On a map served by view, open any module, provider or controller at its line in VS Code or Zed.

  • Custom providers

    useClass, useValue, useFactory, useExisting, string and symbol tokens, forRoot() modules.

  • Arrays across files

    Providers spread from constants such as [...SHARED_PROVIDERS] are followed into the files that define them.

  • Any TypeScript

    The analyzer brings its own TypeScript, so it reads your code whatever version your project uses.

Commands

# source code → cartograph.json
npx nest-cartograph analyze -p apps/api/tsconfig.json -o docs/cartograph.json
npx nest-cartograph analyze --fail-on-cycles

# cartograph.json → map
npx nest-cartograph view docs/cartograph.json --port 5055
npx nest-cartograph view -o cartograph.html
